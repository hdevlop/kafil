The overall structure is promising, but fix these blocking contract issues:

1. Diagnostic secrecy
- `toSafeDetail(Error)` currently includes `error.message`, and tests explicitly expect `connect ECONNREFUSED`. Raw messages can contain connection strings, URLs, tokens, SQL, or settings. This violates the frozen sanitized-diagnostic rule.
- Emit only a stable code plus a safe error classification (normally bounded `error.name`), never `message`, stack, cause, arbitrary object content, or thrown string. Add tests with secrets embedded in Error.message/cause and confirm they never appear.

2. Preserve School logout ordering
- School currently performs auth logout first through `SignOutButton`, then runs `clearSchoolUiPreferences` in `onSuccess`. The new `logoutWithNajmPreferenceCleanup` does cleanup before logout and its test pins that divergence.
- Change the helper to await/propagate auth logout first, then best-effort preference cleanup, then return the exact logout result. If auth logout rejects, propagate the identical error and do not run cleanup (matching `onSuccess`). If cleanup rejects or endpoints fail after a successful logout, it must not replace the successful auth result.
- Also make `clearNajmUiPreferences` truly independent for synchronous injected throws: one throwing endpoint must not prevent attempts to the other endpoints. Test call count/URLs.

3. Remove the shared MAD business default
- `defineNajmPreferences` currently adds `currencies: ["MAD"]` / default `MAD` to every old consumer. This hard-codes Kafil/School business policy in Kit and contradicts the plan's app-owned currency semantics.
- Preserve zero-config legacy consumers without inventing any currency. Ordered currency resolution should be available only when the app explicitly configures a typed currency allowlist/fallback (or through a separate explicitly configured ordered descriptor). Use conditional/additive typing if needed: legacy `resolve()` remains unchanged; an app that wants `resolveOrdered().currency` must configure currency explicitly. Kafil/School fixtures must pass their own `MAD` fallback. No generic USD/MAD/locale default.
- Keep currency sources structurally restricted to institution -> fallback; cookie/user/locale must remain unrepresentable/ignored.
